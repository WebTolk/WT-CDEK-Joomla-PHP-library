# F5: Определить lifecycle повторной конфигурации Watchfield

Приоритет: **P3 / решение контракта**. Статус: **Открыта; необязательная возможность до решения**.

## Подтверждение

Исторический probe: существующий DOM target не читает заменённые options/provider при scan. Обычный статический XML оператором проверен.

## Места в коде

- `lib_webtolk_wtcdek/media/js/wtcdek-watchfield.js`

## Проблема

Конфигурация читается при создании state; scan прежнего target не применяет новое data-watchfield-options или Script Options. Замена target новым работает.

## Требуемое изменение

Явно выбрать контракт scan/refresh/reconfigure либо неизменяемую конфигурацию с заменой target. Код менять только после решения о поддерживаемом lifecycle.

## Критерии приёмки

- [ ] Контракт описан в документации.
- [ ] При reconfigure поддержке старый запрос отменяется, новые параметры применяются, stale response игнорируется.
- [ ] При immutable-политике описана обязательная замена DOM target; обычный XML не блокируется этой задачей.
