# F2: Обновлять цепочку после программной смены ПВЗ

Приоритет: **P2**. Статус: **Открыта; отдельный пограничный сценарий**.

## Подтверждение

Историческое Chrome-воспроизведение от 12.10; новый браузерный прогон не выполнялся. Ручная приёмка ordinary Watchfield учтена.

## Места в коде

- `lib_webtolk_wtcdek/media/js/wtcdek-deliverypoints.js`
- `lib_webtolk_wtcdek/media/js/wtcdek-watchfield.js`

## Проблема

Renderer изменяет native select программно и посылает options-updated; Watchfield-наблюдатель слушает input/change, поэтому следующий потребитель может оставить старый код.

## Требуемое изменение

Повторить город -> ПВЗ -> зависимый потребитель. Если подтверждено, уведомлять registry о фактической смене значения; определить дедупликацию и защиту от циклов.

## Критерии приёмки

- [ ] Программный clear/replace ПВЗ инвалидирует следующий consumer.
- [ ] Неизменное значение не вызывает лишние запросы.
- [ ] Циклические зависимости не создают бесконечный цикл; ручной выбор и FancySelect работают.

Сохранить Joomla 4.2.7+ и PHP 7.4. Не запускать реальные запросы CDEK, менять стенд, выпускать ZIP/релиз или исправлять соседние задачи без отдельного scope. Этот файл — проектная задача; native PF ledger отсутствует, проект работает через .webtolk.
